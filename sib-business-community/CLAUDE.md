# SIB Business Community 提案資料 — 制作ガイド

このファイルが本プロジェクト（`sib-business-community/`）の唯一の基準。作業前に必ず読むこと。

---

## 1. 事業の考え方（最重要・戦略の前提）

### 二段構造

```
PHASE 1  経営者コミュニティ単体で価値が成立する状態をつくる   ← いまここ
PHASE 2  学生コミュニティが育った段階で、学生接点を追加価値として強化
PHASE 3  企業向けサービス（SNS運用・学生PJ・採用広報・AI活用 等）へ展開
```

- **経営者コミュニティの価値を、学生コミュニティに依存させない。**
  学生側は規模拡大にも価値検証にも時間がかかる。学生が伸びなかった場合に
  経営者コミュニティまで弱くなる構造を避けるための設計。
- 「学生とつながれるから入るコミュニティ」ではなく、
  **「経営者コミュニティとして入る価値があり、その先に学生・若者・SNSとの接続もある」**。

### 一言で

> 経営課題を共有し、必要な人・企業・情報・機会につながり続ける経営者ネットワーク。

異業種交流会・飲み会・名刺交換会にはしない。

---

## 2. 禁止事項（絶対に戻さない）

| 禁止 | 理由 |
| --- | --- |
| 「湘南企業と学生をつなぐ」をメインコピーにする | 学生依存の構造に戻る |
| 「湘南で最も若者接点に強い」をコンセプトにする | 同上 |
| 学生アクセスをコミュニティの中核価値として前半に置く | 同上 |
| 企業課題→SIB→学生→成果物 を基本サービスとして見せる | 基本サービスではない |
| 学生リサーチ・学生プロジェクトを**会費に含める** | SIBの工数が発生するものは原則別料金 |
| 毎月学生接点がある前提でコミュニティを設計する | 実態と合わない |
| 若手採用だけをメイン課題にする | 対象ニーズが狭すぎる |
| 「学生だから安く動ける」という見せ方 | 価値の見せ方として誤り |

### 表現ルール（従来から継続）

- 成果保証をしない。「3か月で必ず案件が生まれる」は禁止。
  「**関係 → 相互理解 → 新しい機会**が生まれやすい仕組み」として書く。
- 料金は初期実証フェーズのもので、**実証を通じて調整予定**であると明記する。
- 他コミュニティを否定しない。「目的が違い、併用可能」というスタンスを保つ。

## 3. サービス内容の定義

### 3つの中心価値

1. 経営者同士の学び・情報交換（テーマ別ラウンドテーブル）
2. 企業同士のビジネスマッチング（課題 × 他社の強み・資産）
3. 新しい人・情報・事業機会が継続的に入る状態

### 活動（7つ）

テーマ別ラウンドテーブル／課題ベース企業マッチング／会員企業紹介／事業機会の流通／
会員限定イベント（3か月に1回程度）／少人数の交流会／経営課題の壁打ち

### 料金

- 初期実証フェーズ：**月額 20,000円**、まずは1か月単位
- 今後の想定：3か月 60,000円 を基本契約に（**「今後の想定」と明記する。確定ではない**）
- 別料金サービスは個別見積

### 会費内 / 別料金の線引き

| COMMUNITY（会費内） | PROJECT（別料金・個別見積） |
| --- | --- |
| 経営者コミュニティ参加 / テーマ別ラウンドテーブル / 会員限定イベント / 企業紹介 / 経営者・企業マッチング / 協業機会の流通 / 経営課題の簡易相談 / SIBからの情報提供 | SNS運用 / 本格的な学生リサーチ / 学生プロジェクト / 採用広報 / LP・Web制作 / 動画制作 / AI活用支援 / イベント企画運営 |

**判断基準：SIB側に本格的な工数が発生するものは原則として別料金。**

### 対象

湘南・神奈川を中心とした経営者／役員／事業責任者／人事責任者／新規事業責任者。
企業規模 10〜300名（特に 20〜100名）。エリアは湘南・神奈川 → 横浜・川崎・東京 → 首都圏。

## 4. デザイン規約

### 方向性

上場企業／BtoB SaaS／Premium Business Community／Strategy Deck。
学生団体の資料に見えないこと。

### カラー

```
--navy    #0B2545   基調
--navy-2  #14385F
--blue    #1F5FA9   見出しラベル・罫線
--blue-2  #4A87CC
--sky     #E9F0F8 / --sky-2 #F5F8FC   面
--line    #D7E1EC   罫線
--muted   #55697F   補足テキスト
--accent  #C43D8E   差し色（マゼンタ・少量）
--violet  #6E42D1   差し色（パープル・少量）
--accent-grad  linear-gradient(135deg, var(--violet), var(--accent))  重要箇所のみ
```

グラデーションは表紙・クロージングCTA・循環図の中心番号など「重要な数箇所」に限定し、
資料全体をグラデーション塗りにしない。

**過度なグラデーションは禁止。** navy 面の緩やかな1段グラデーションまで。

### フォント

```
-apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans",
"Yu Gothic", "Meiryo", "SIB Fallback JP", sans-serif
```

- **外部 Web フォントは読み込まない。** OS 標準のゴシックのみ。
- 末尾の `SIB Fallback JP` は、日本語システムフォントを持たない headless 環境で
  書き出したときだけ使われる同梱フォント（`fonts/`）。実機では常に OS フォントが優先される。
- `fonts/Noto-Sans-JP-{400,500,700,900}.woff2` は Noto Sans CJK JP から
  `pyftsubset` で切り出したサブセット。**常用漢字だけでなく CJK統合漢字
  （U+4E00–U+9FFF, U+3400–U+4DBF）を丸ごと含めてある**（1ファイル約9〜10MB）。
  過去に一部の文字（例：「入」）だけがサブセットから漏れていて、headless環境で
  その文字だけシステムの別フォント（IPAGothic）にフォールバックし、同一文章内で
  フォント・太さ・字形が混ざって見える不具合があったため。**サブセットを絞り直す
  場合は、この不具合が再発しないことを screenshot と PDF ラスタライズの両方で
  確認すること。** 実機のブラウザでは Hiragino Sans 等が先に一致するため、この
  フォントの中身は実際の見た目には影響しない。

### 文字サイズ（1920×1080 基準・**24px 未満は1箇所も禁止**）

| 用途 | サイズ |
| --- | --- |
| ページタイトル | 52〜68px |
| 重要コピー | 40〜56px |
| 本文 | 28〜34px |
| 補足・ラベル・ページ番号 | 24〜28px |

- ページ下部に小さく注意書きを置くレイアウトは禁止。
  重要な注意事項は `.callout`（26px・面あり）として本文に組み込む。
- 入らない場合の対応順序：**文章を削る → ページを分ける → 図解する**。
  文字を小さくして詰め込むことは禁止。

### 情報量・レイアウト

- 1ページ1メッセージ。箇条書きは3〜5個。1ブロック2〜3行まで。
- 1ページの主要要素は1〜3個。カードを乱用しない。罫線・余白・図形で構造を示す。
- ページごとに構図を変える（左右分割／中央構図／大型数字／タイムライン／比較／フロー）。

## 5. 実装

- `index.html` / `style.css` / `app.js`（16:9・1920×1080・全20ページ）
- `app.js`：← / → / Space / PageUp / PageDown でページ移動。
  スクロール連動の控えめなアニメーション（Fade / Slide / Line Draw / Stagger）。
- `?static=1` を付けて開くとアニメーションを無効化し完成状態で描画する。
  **書き出しは必ず `?static=1`**（`scripts/export.js` が自動で付与）。
- 印刷 CSS（`@media print`）でアニメーションを無効化し、1ページ1スライドで出力。

### 書き出し

```bash
node scripts/export.js          # PDF + PNG
node scripts/export.js --png    # PNG のみ
node audit.js                   # 24px未満の文字／枠外はみ出しの自動検査
```

### PDF 出力で壊れる CSS（使用禁止）

| 禁止 | 症状 | 代替 |
| --- | --- | --- |
| `background-clip: text` | 文字が矩形の塗りになり読めない | 単色 `color` |
| 大きな `box-shadow`（大ぼかし＋負スプレッド） | 灰色の矩形として焼き込まれる | 内側1pxハイライト／影なし |
| `filter: blur()` | ラスタライズされ粗くなる | gradient のストップで表現 |

### 完成前の必須チェック

```bash
node audit.js   # → 「24px未満: 0」「枠外にはみ出し: 0」であること
```

```bash
python3 - <<'EOF'
import pymupdf
d = pymupdf.open('output/SIB_Business_Community_提案資料.pdf')
d[12].get_pixmap(dpi=110).save('/tmp/p13.png')   # 画としても確認する

```

PNG が正常でも PDF だけ壊れることがあるため、**必ず PDF もラスタライズして目視する。**

## 6. ページ構成（全20枚）

外部の初対面の読み手（転送先の経営者）が単体で理解できることを前提に、
起（Why）→承（What）→転（SIBだからこそ／差別化・将来価値）→結（料金・対象・CTA）の順で構成。

| No | 内容 | 構図 |
| --- | --- | --- |
| 01 | COVER（メインコピー＝つながりを、次の事業機会へ。） | 大型タイポ・navy |
| 02 | WHY 「つながり」は事業につながっているか | 3カラム（現状→でも） |
| 03 | CONCEPT（名刺交換で終わらないネットワークへ） | 中央・大型タイポ |
| 04 | HOW IT WORKS | 循環図（5ステップ・中心にSIB） |
| 05 | 3 CORE VALUES（学ぶ／つながる／生まれる） | 3カラム・円バッジ |
| 06 | ACTIVITIES | 大3＋補助4（均等グリッドにしない） |
| 07 | THEME ROUNDTABLE | 左右分割・当日の問い（例） |
| 08 | BUSINESS MATCHING（NEEDS × ASSETS） | 式＋事例3行 |
| 09 | COMMUNITY EXPERIENCE | フィード型リスト |
| 10 | 3 MONTH JOURNEY | 横タイムライン |
| 11 | POSITIONING（規模ではなく、深さで勝つ。） | 強み／弱み2カラム＋勝ち筋フロー |
| 12 | COMPARISON（それぞれ、得意な役割が違います。） | ◎○△－マトリクス（11軸） |
| 13 | ABOUT SIB（運営主体の説明） | 左右分割。数値は要確認のみ記載 |
| 14 | WHY SIB | 4カラム・navy |
| 15 | FUTURE VALUE | PHASE 1→3・navy |
| 16 | SCOPE | 会費内／別料金の2分割 |
| 17 | PRICING | 大型数字・左右分割 |
| 18 | WHO WE'RE LOOKING FOR（対象・お願いしたいこと） | 左右分割・チェックリスト |
| 19 | EARLY MEMBER（初期メンバーだからこそ） | 4パーク・ポジティブな訴求 |
| 20 | NEXT STEP / CLOSING | 中央・navy・2択CTA |

13ページ「ABOUT SIB」に記載する実績・数値は必ず「実際に確認できるもの」だけに差し替える。
未確認の企業名・行政連携・具体的な人数や回数は記載しない。

### POSITIONING（p11）とCOMPARISON（p12）の役割分担

- p11 は「SIBは何でもできる」と誤読されないための正直な強み・弱みの開示。
  弱みは婉曲にせず明記しつつ、末尾の「だから、こう勝つ」で前向きに締める。
- p12 の比較表は **SIB列だけが全部◎にならないようにする**。◎は「特に強い」の
  意味であり他列にも普通に付く。SIB列のアクセント色（マゼンタ）は◎の記号自体にのみ
  乗せ、○△－では乗せない — そうしないと「自社に都合の良い比較表」に見える。
